# Architecture rules
- Scheduled-order screens consume server-local RPC projections and slot timestamps; acceptance persists staged rescheduling only on confirmation and delegates status decisions to the database; store timezone lookups share a cached hook to avoid inconsistent labels.
- Panel current-store lookups must use the validated active store from useStoreAccess and wait for access resolution; owner fallbacks are reserved for master flows without an active store to prevent multi-store mixing.
- Store UaZapi webhook subscriptions and message guards share Central entitlement resolution (active module, store override, then plan) to prevent divergent behavior.
- Synchronize store UaZapi webhooks after persisted Central access or plan changes; synchronization failures must warn without undoing saved access changes.
- Bulk webhook reconciliation is master-only, paginated and limited to registered store instances; never update the master instance or global webhook.
- Booking URL-button notification formatting and transport live in a shared server helper; confirmation/reschedule and reminder reuse it to preserve the same whitelist and fallback behavior.
- Booking button signatures are enforced by the shared server payload builder, not merchant settings or plans; reserve server-only per-store white_label_buttons overrides disabled by default for future master control.
- Public pricing uses one projected server catalog and a shared query cache; negotiated proposals and existing subscriber prices remain historical values, not catalog rewrites.
- Annual presentation, master previews and future invoice generation share a pure calculateAnnualPricing helper; round monthly before annual totals, persist explicit store cycles only on signup/plan selection, and preserve legacy null-cycle invoice behavior.
- Public and signup plan cards share a configurable highlight catalog and module-based grouped details; billing selection is controlled when used for signup or plan changes.
- Pending plan approvals carry explicit billing choices in tagged notes; authenticated master approval and PIX confirmation persist the choice only on activation, preserving negotiated store fields and untagged legacy approvals.
- Browser and Deno import the same dependency-free billing helpers from the shared server directory, preventing annual rounding and legacy-cycle divergence.
- Founder slots are allocated transactionally by a service-role-only database function after master authorization in the pricing endpoint; previews never reserve slots.
